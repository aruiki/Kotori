# 作業カード

1枚のカード = 1つの PR。番号の小さい順に進める(依存がある場合はカードに書いてある)。
終わったカードは `done/` に移す。進め方は `docs/DEVELOPMENT.md` の「3. 作業の流れ」。

## カードの形

新しいカードを書くときはこの形にそろえる。

```markdown
# NN: 題(一行)

- 仕様: SPEC の節と REQ ID
- 前提: 先に終わっているべきカード(なければ「なし」)
- 規模の目安: 差分の行数

## 目的
何ができるようになるか。2〜3 行。

## 読むもの
変更の前に読むファイルと節。

## 手順
1. 具体的に(ファイル名・関数名・型名を書く)。

## テスト
追加するテストの名前と、確かめること。

## 完了条件
- [ ] `just ci` が通る(Windows のコードなら CI の windows ジョブも緑)
- [ ] ほかの具体的な条件

## 注意
はまりどころ。
```
