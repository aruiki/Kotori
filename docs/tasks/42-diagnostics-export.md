# 42: 診断情報の書き出しとクラッシュのダンプ

- 仕様: SPEC 13.3(ミニダンプをローカルに保存、設定画面に「診断情報を書き出す」)、REQ-15-2(入力内容を記録しない)、
  docs/adr/0037 の G6
- 前提: なし
- 規模の目安: パッチ 200〜300 行

## 目的
利用者から「変換が遅い」「落ちた」と言われても、今は手がかりがない。入力内容を含めずに、版・環境・AI の状態・
最近の異常をまとめて 1 つのファイルに書き出し、Issue に添付してもらえるようにする。送信はしない。

## 読むもの
- Mozc の `base/crash_report_handler*`(OSS 版では無効)、`base/logging`、`gui/config_dialog`(「AI 変換」タブ)
- docs/adr/0026(AI の状態の表示)、`mozc/patches/README.md`

## 手順
1. `mozc_server.exe` に未処理例外のハンドラーを入れ、`%USERPROFILE%\AppData\LocalLow\Kotori\crash\` に
   ミニダンプ(`MiniDumpNormal`。メモリの中身を含めない)を最大 5 個まで残す。
2. 設定画面の「AI 変換」タブに「診断情報を書き出す」ボタンを足し、zip を保存する: Kotori と Mozc の版、Windows の版、
   CPU・GPU・ドライバー・VRAM、設定(品質・AI の予測・モデル)、AI の状態(docs/adr/0026)、変換の時間の統計
   (回数・中央値・最大。既にあれば)、ミニダンプ。**読み・候補・確定した文字・前の文は入れない。**
3. 書き出す前に中身の一覧を見せる。

## テスト
- 単体テスト: 診断情報を作る関数に、読みや候補を含む状態を渡しても出力に現れない。
- わざと落とす環境変数(開発用)でダンプができ、6 個目で古いものが消える。
- `capture_window.py` でボタンを含む画面を、倍率・ダークモードで見る。

## 完了条件
- [ ] 書き出した zip を開いて、入力内容が入っていないことを確かめ、PR に中身の一覧を貼る
- [ ] `stress_test.py` で異常終了なし、変換の時間が変わらない。CI が緑

## 注意
- ダンプは `MiniDumpWithFullMemory` にしない(入力内容がメモリに残っている)。
- 実験中にビルドしない(`AGENTS.md`)。
