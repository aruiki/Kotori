# 43: 利用者向けの文書と窓口

- 仕様: SPEC 15 章(脆弱性は 14 日以内に修正)、docs/adr/0037 の G6
- 前提: なし(42 ができたら、診断情報の添付を案内に足す)
- 規模の目安: 文書 300 行

## 目的
今は README だけで、データの置き場、アンインストールで残るもの、困ったときの対処、既知の制限がまとまっていない。
不具合と脆弱性を報告する窓口もない。知らない人が入れて、困ったときに自分で解決するか、報告できるようにする。

## 読むもの
- `README.md`、`mozc/release-notes.md`、`docs/ACCEPTANCE.md`、docs/adr/0024・0034(GPU のない PC、VRAM を空ける)

## 手順
1. `docs/USER_GUIDE.md`: 入れ方・切り替え・品質の選び方・AI の予測と Tab・ユーザー辞書・更新(上書き)・
   アンインストール(残るもの: `%USERPROFILE%\AppData\LocalLow\Kotori` の設定・学習・辞書と、その消し方)・
   プライバシー(通信しない、何を保存するか)。
2. 同じ文書の「困ったとき」: SmartScreen の警告、入力できないアプリ、AI が動かない(設定の「AI の状態」の見方)、
   遅い・固まる(品質を下げる)、ゲーム中の VRAM、元の IME に戻す。
3. 「既知の制限」: GPU のない PC で長い文を打ってすぐ Space、内蔵 GPU を使わない、ARM64 は対象外など。
4. `.github/ISSUE_TEMPLATE/`: 不具合(版、Windows、GPU、品質、アプリ、手順。入力内容を貼らないよう注意書き)、
   誤変換(読み・期待・実際。これは入力内容を書いてもらう)、要望。
5. `SECURITY.md`: GitHub の非公開の脆弱性報告で受け付ける。14 日以内の修正を目標にする。
6. README の「インストール」「よくある質問」から `docs/USER_GUIDE.md` へつなぐ。

## テスト
