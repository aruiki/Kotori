# 33: 表記だけが違うときは Mozc の表記を優先する(保留)

- 仕様: docs/adr/0016、0023、0027、docs/IMPROVEMENT_PROPOSALS.md の案 07
- 前提: 30
- 規模の目安: パッチ 60 行、調整用のセット 60 問

## 目的
最終評価用のセット(300 問)で、Standard / High が Mozc の正しい表記を口語的な表記に変えた(「鍵」→「かぎ」、
「何」→「なに」、「見た」→「観た」、「札幌」→「さっぽろ」、「五十音順」→「５０音順」)。LLM が口語の表記を好むため
(Low は LLM を使わないので起きにくい)。読みが同じで表記だけが違うなら、Mozc の表記(辞書と利用者の学習を反映)を
優先する。

## 読むもの
- `rewriter/lm_rewriter.cc` の `CheckResizeSegmentsRequest`(点数と選択)、docs/adr/0023(LLM の重み)
- eval/README.md の kotori-heldout の結果(**調整に使わない**。傾向を知るためだけ)

## 手順
1. 調整用の表記のセット `eval/sets/kotori-notation.json` を作る(60 問ほど。heldout と別の文。漢字・かな・カタカナ・
   数字の表記が分かれる語を含む日常の文。許容する表記の基準は heldout と同じ)。
2. 選ばれた文と Mozc の 1 位が、同じ区切り・同じ読みで表記だけ違うかを判定する(文節ごとの読みの比較)。
3. 表記だけの違いなら、点差が小さい(閾値)ときは Mozc の 1 位を残す。閾値は調整用のセット(AJIMEE・日常・慣用句・
   ニュアンス・表記)で選ぶ。
4. 最後に heldout で結果だけを報告する。

## テスト
- `eval_all.sh` と表記のセットで、Mozc より悪くなった問題が減り、ほかが下がらない。

## 完了条件
- [ ] 表記のセットで Standard が上がり、AJIMEE・日常が下がらない
- [ ] CI(Mozc (Windows))が緑

## 進み具合(2026-10-01、保留)

調整用の表記のセット `eval/sets/kotori-notation.json`(60 問)を作って測ると、Mozc 単体 86.7%、Standard 95.0%、
Low 93.3%。heldout で見えた「LLM が Mozc の表記を口語に変える」誤りは、このセットではほぼ起きなかった
(Mozc が正しく Standard が誤ったのは「電気を消してね」→「電気を消して寝」の 1 問)。調整に使える手がかりがないまま
規則を入れると heldout に合わせた調整になるので、保留にする。表記の誤りを集めた調整用の問題が増えたら再開する。
