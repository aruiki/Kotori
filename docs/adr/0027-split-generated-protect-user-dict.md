# 0027: AI が生成した文を文節に分け、ユーザー辞書の語を AI で変えない

- 状態: 採用
- 日付: 2026-09-30
- 関係: docs/adr/0016、0020、docs/IMPROVEMENT_PROPOSALS.md の案 06・07

## 問題

- zenz が生成した文を選ぶと、全体を 1 つの文節にしていた(docs/adr/0016)。ほぼ正しい文で一語だけ違うとき、
  Shift + ←/→ で区切り直してから選び直す必要があった。
- AI が文全体で選び直すとき、利用者がユーザー辞書に登録した表記(Mozc の 1 位)も置き換えうる。

## 決定

- 生成した文が読みに合うかを確かめる `MatchesReading` で、表記と読みの対応(辞書の語・かな・数字などの単位)
  を取り出す。ひらがなで終わる単位の後に、ひらがな以外で始まる単位が来たら文節を区切る
  (`SplitIntoSegments`。「資料を|送りますので|ご確認|ください」)。文節は最大 8 個(Mozc の切り直しの上限)で、
  超えた分は最後の文節につなぐ。対応が取れないときや、つないだ結果が読み・表記と一致しないときは全体を
  1 つの文節にする(前と同じ)。辞書に句として入っている語(「明日の会議」)は途中で区切らない。
  `KOTORI_LM_SPLIT=0` で前の動きにできる。
- ユーザー辞書の語(`converter::Attribute::USER_DICTIONARY`)を守る: Mozc の 1 位の文がユーザー辞書の語を含めば
  文全体の選び直しをしない。文節の 1 位がユーザー辞書の語なら、選んだ文を当てはめず、文節ごとの並べ替えも
  しない。

## 結果

- 精度(前の文あり)は変わらない: AJIMEE Low 88.0%、Standard 91.5%、High 92.5%。日常の文 97.5%。
- 日常の文 81 問(Standard)で、1 文節のままの文 8 → 4、平均の文節数 2.30 → 2.36。
- `rewriter/lm_rewriter_test.cc`(`bazelisk test //rewriter:lm_rewriter_test`)で区切り方を確かめる。
  Mozc の CI は MSI のビルドだけなので、手元で回す。
- ユーザー辞書の保護は、辞書を登録した実機で確かめる(docs/ACCEPTANCE.md に足す)。
