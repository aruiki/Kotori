# 0037. 製品版(v1.0)への道

- 日付: 2026-10-01

## 背景

精度(Standard で AJIMEE 91.5%、最終評価用 300 問で 96.3%)、負荷(GPU の稼働率 68.6% → 42.6%、使わないときの
VRAM 0)、GPU のない PC での動作、上書きインストール、設定画面のアクセシビリティまで、v0.3.0-beta.8 で一通りそろった。
実際の IME で比べても、AJIMEE・日常・同音語・人名で Google 日本語入力と Microsoft IME を上回っている(README)。

一方で、配布物と仕様は「開発者本人が私用で使うベータ」のままになっている。製品として人に配るのに足りないものを、
2026-10-01 の main と、公開中の MSI(v0.3.0-beta.8 を展開した中身)で調べた。

| 見た所 | 今の状態 | 製品版で困ること |

## 決めたこと

### 1. v1.0 の定義

**v1.0 = 署名された `Kotori64.msi` を、知らない人がそのまま入れて、普段の IME として使い続けられる版。**
機能は今の v0.3.0-beta.8 で足りている(新しい機能は v1.0 の条件にしない)。足りないのは「配る」「直す」「信じてもらう」
ための部分。

### 2. 段階

| 段階 | 版 | 入る条件 | 出す所 |
| --- | --- | --- | --- |
| ベータ(今) | `0.3.0-beta.N` | — | GitHub Releases(Latest) |
| RC | `1.0.0-rc.N` | カード 40〜43 が済み、同梱物と表示が製品版のもの | GitHub Releases(プレリリース) |
| 正式版 | `1.0.0` | 下の「v1.0 の出荷条件」をすべて満たす | GitHub Releases(Latest)、のちに winget |
| 修正版 | `1.0.x` | 不具合・脆弱性の修正だけ。脆弱性は報告から 14 日以内(SPEC 15 章) | 同上 |

ベータの間に入れた改善(ATOK に近づける作業など)は、RC に入ったら止めて、RC では不具合の修正だけにする。
新しい改善は 1.1 に回す。

### 3. v1.0 の出荷条件

| # | 条件 | 確かめ方 | 誰が |
| --- | --- | --- | --- |

| G2 | 落ちない・固まらない: 24 時間の負荷試験で異常終了・ハングなし、`mozc_server.exe` のメモリが 10% を超えて増え続けない(REQ-13-1)。GPU と CPU の両方 | `stress_test.py` を 24 時間 | エージェント(開発機) |

### 4. 署名の手段

| 案 | 費用 | 条件 | 評価 |
| --- | --- | --- | --- |
| SignPath Foundation(OSS 向けの無償の署名) | 無料 | OSS のライセンス、公開リポジトリ、CI でビルドしていること。審査がある | **第一候補**。この条件をすべて満たしている。CI に署名の手順を足すだけ |
| Azure の Trusted Signing(Artifact Signing) | 月額の有料 | 本人確認。個人で使えるかは国と時期で変わる | SignPath が通らなければ |
| OV / EV のコード署名証明書 | 年数万円 | ハードウェアの鍵(CI では扱いにくい) | 最後の手段 |

申し込みはメンテナの名前でしかできないので、メンテナに頼む(カード 44)。署名がない間も RC は出す(未署名と書く)。

### 5. 更新の仕方

実行時にネットワークに出ないので、**自動更新と更新の確認は作らない**(REQ-15-1 を優先)。更新は、利用者が新しい MSI を
上書きで入れる(beta.6 から入れ替わる)。正式版のあとは winget に載せ、`winget upgrade` で更新できるようにする
(winget は Kotori の外のしくみ。カード 47)。

### 6. 変えないこと

- 機能・品質の段階(Low / Standard / High / Unreal)と既定(Standard)。
- 同梱するモデル(MSI の上限から、足すならどれかを外す)。
- 旧 Rust 版は v1.0 に含めない(評価の基準としてリポジトリに残す)。
- ARM64、macOS、Linux は v1.0 の対象外。

## メンテナに頼むこと

1. **SignPath Foundation への申し込み**(または署名の手段の決定)。リポジトリの持ち主の名前で行う必要がある。
2. **SPEC の改訂の承認**(カード 46 の PR と、待っている #113)。
3. **実機の確認**(`docs/ACCEPTANCE.md`)。GPU のある PC と GPU のないノート PC。
4. **winget への提出の承認**(正式版の後。外部のリポジトリへの PR になるため)。
