# 0025: 予測のキャッシュを設定で区切り、キャッシュのない Tab に時間の上限を設ける

- 状態: 採用
- 日付: 2026-09-30
- 関係: docs/adr/0019、0021、0024、docs/IMPROVEMENT_PROPOSALS.md の案 03・04

## 問題

- 入力中の AI 予測のキャッシュは、読みと前の文だけで再利用していた。品質・AI モデル・LLM のファイルを
  変えても、前の設定で作った予測が出うる。AI を切ったときやシークレットモードでも、覚えた予測が残った。
- キャッシュのない Tab(打ってすぐ Tab)は、その場で予測を作るので最大約 1 秒待たせた(docs/adr/0021)。

## 決定

- キャッシュのキーに、予測を変える設定の署名(品質、AI モデル、LLM のファイル)を含める(`CacheKey`)。
- AI を切ったとき、シークレットモード(`ConversionRequest::incognito_mode`)、LLM の予測を使わないときは、
  覚えた予測とまだ始めていない予測の仕事を捨てる(`ClearPredictions`)。シークレットモードの Tab では
  AI の予測を出さない。
- キャッシュのない Tab で予測を作る時間に上限を設ける(既定 0.7 秒、`KOTORI_LM_TAB_BUDGET`)。超えたら
  AI の予測は出さず(Mozc の予測は出る)、途中の結果は覚えない。

## 結果(RTX 3060、決まった言い回し 29 問、`eval_predict.py --warm 0`: 打ってすぐ Tab)

| 上限 | 当たり | Tab の応答(中央値 / 最大) |
| --- | ---: | --- |
| なし | 17/29 | 332 / 863 ms |
| 0.4 秒 | 12/29 | 362 / 451 ms |
| **0.7 秒** | **18/29** | 388 / 783 ms |

0.4 秒では多くの問題で打ち切られるので、当たりを保つ 0.7 秒にした。1 秒待ってから Tab(キャッシュを使う)は
16/29、中央値 37 ms で変わらない。
