# 0019: 打鍵ごとの遅れをなくす、入力中の候補に AI の予測を出す、名前とアイコン

- 状態: 採用(メンテナの要望: 「Standard 以降はラグがひどい」「Tab の予測がつながっていない」
  「Tab を押す前に候補を表示しないと意味がない」「IME のアイコンが Mozc のまま。安直でない良いデザインに」
  「名前を Kotori日本語入力 に」)
- 日付: 2026-09-30
- 関係: docs/adr/0018(1 章の速さと 2 章のアイコンを改める)

## 1. 打鍵ごとの遅れ

原因は、Mozc の「入力中の候補」(SUGGESTION)が、打鍵ごとにリアルタイム変換(`StartConversion`)を
呼び、その中で AI の変換(生成と採点、Standard で 80 ms)がまるごと動いていたことだった。品質を上げるほど
1 打鍵が重くなる。

- リアルタイム変換(`options.skip_slow_rewriters`)では、AI の書き換えも文節の切り直しもしない。
  AI の変換は Space(CONVERSION)と Tab(PREDICTION)のときだけ。
- 打鍵ごとの応答: 60〜260 ms → 1〜3 ms(`converter_main` で 1 文字ずつ送って計測)。

## 2. 資源(インストール先のサーバー、RTX 3060、Standard)

採点の一括投入の大きさ(`n_batch` / `n_ubatch`)が 4096 で、logits の作業領域が 2.5 GB あった。
512 にし、候補を 512 トークン以内の組に分けて投入する(速さは同じ)。

| | 前 | 後 |
| --- | ---: | ---: |
| VRAM | 4711 MB | 1628 MB |
| メモリ(ワーキングセット) | 1953 MB | 440 MB |
| メモリ(プライベート) | 5599 MB | 2133 MB |
| 待機中の CPU | 5 秒で 156 ms | 0 |

待機中は何もしないので、モデルを起動時に読んで常に持っておく(0018 の `preload_`)方針のままにする。

## 3. 入力中の候補(SUGGESTION)に AI の予測を出す

Tab を押してから予測を作るのでは遅い。打鍵ごとに裏のスレッドで予測を作り、次の打鍵の候補に出す。

- `LmRewriter` は SUGGESTION も受ける。その場では計算しない: 裏で作った予測のうち今の読みに合う
  ものを最大 2 件、候補の先頭に入れ(説明は「AI」)、今の読みの計算を裏のスレッドに頼むだけ。
- 裏のスレッド(`worker_`)は、最新の読みだけを計算する(古い頼みは捨てる)。変換や Tab の要求が来たら
  (`urgent_`)途中でやめて GPU を譲る。結果は読みごとに 32 件まで持つ。
- 予測が今の読みに合うかは、予測の続きの読みを裏で求めておき、文字列の比較だけで決める
  (打鍵ごとに辞書を引かない)。読みはひらがなの所は辞書を引かず、漢字などの所だけ逆引きする
  (95〜250 ms → 0〜36 ms)。
- Low でも予測のために LLM を読み込む(変換の採点には使わない)。LLM を使わない設定(自動で GPU がないとき、zenz のみ)では予測しない。
- 1 件の計算は 130〜200 ms(変換 20 ms、生成と並べ替え 110 ms、読み 0〜36 ms)。0.15 秒おきに打つと、
  1 打鍵前の読みの予測が出る(「よろし」で「よろしくお願いします」)。応答は 1〜3 ms のまま。

## 4. 名前

表示名を「Kotori日本語入力」(英語は Kotori Japanese Input)にする。言語の一覧、設定画面、
インストーラ、ショートカット、候補ウィンドウの名前。内部の名前(レジストリ、フォルダ、サービス)は
Kotori のまま変えない(上書きインストールを壊さないため)。言語の一覧の名前は Windows が資源の番号で
覚えているので、番号を 201 → 202 に変えた。

## 5. アイコン

0018 の小鳥の絵は、名前をそのまま絵にしただけで幼く見える。作り直した(`mozc/tools/kotori_mark.py`)。

- マーク: 明朝の「こ」に朱の点。点は句点(文が決まる=変換)と印を兼ねる。藍のタイル(#242C5C → #0C102A)
  に白。書体は Noto Serif JP(ExtraBold、OFL)。
- 32px 以下は明朝の細い線が潰れるので、Noto Sans JP(Black)で描き、タイルを大きくする。
- 設定は白い歯車に朱の芯、辞書は「辞」に朱の点。
- 入力モード(あ・カ・ｶ・Ａ・A・×)は、Windows の IME と同じく白い字に濃い縁取り(色の地を付けない)。
  タスクバーの明暗どちらでも読める。半角は下線。
- インストーラの画像も同じマーク。
- `.ico` の中身は BMP にする。PNG にすると古い Windows SDK の `rc.exe` が RC2176 で止まる
  (CI の MSI の失敗はこれだった)。

## 6. 読みを写しただけの生成を選ばない

「きょうきゅうきょきゅうかをとった」が「供給きょきゅうかをとった」になった(Mozc 単体は「今日急遽休暇を
取った」)。zenz が読みを写した生成を高く採点し、Standard では LLM が zenz の上位 4 件しか採点しないので、
ラティスの答えが比べられずに負けた。

- ラティスの 1 位は必ず LLM で採点する。
- 生成した文のひらがなが、ラティスの 1 位より 4 文字以上多ければ除く(Low でも効く)。

AJIMEE(前の文あり): Low 84.5% → 84.5%、Standard 90.5% → 90.5%、High 91.5% → 91.5%。
