# 0021: Tab を待たせない、長い入力で固まらない

- 状態: 採用
- 日付: 2026-09-30
- 関係: docs/adr/0018、0019、0020

## 問題

負荷試験(いろいろな読みで入力中の候補・変換・Tab を交互に送る。長さ 1〜300 文字、記号・英数字・
絵文字を含む)と、Tab の応答時間の計測で次が分かった。

- Tab(予測)は、入力中の候補のために裏で作った予測を使わず、毎回計算し直していた(約 0.5 秒)。
- 長い読みの変換が遅い(250 文字で 5〜8 秒)。文節ごとの見直しが、文節ごとに 1 回ずつ採点するため。
  AI の生成も 120 文字で 0.8〜1 秒かかる。
- 裏の予測は生成の途中で止まれないので、Tab や Space が来ても最大 1〜2 秒待たせることがあった。

## 決定

- Tab は、裏で計算済みの予測が今の読みに合えばそれを使う。なければその場で計算する。
- 裏のスレッドは、軽い予測(次の打鍵に間に合わせる)を出したあと、次の打鍵が来ていなければ、Tab と
  同じ重さで作り直す。次の打鍵が来たら作り直しはやめる(軽い予測はやめない)。
- 裏の生成は 1 トークンごとに止められる(`ZenzScorer::SetThreadCancel`)。変換や Tab が来たらすぐ
  GPU を譲る。
- 長い読みの上限: 生成は 120 文字まで、予測は 40 文字まで。文節が 16 を超えるときは文節ごとの
  見直しをしない(文全体の選択だけ)。生成の上限を 80 文字にすると AJIMEE が 1 問落ちた
  (80 文字を超える問題が 5 問ある)。

## 評価

Tab(決まった言い回し 29 問、`mozc/eval_predict.py --warm 秒`: 1 文字ずつ 0.15 秒おきに入力中の候補を
出し、指定の秒数待ってから Tab):

| Tab を押すまで | 当たり | 文の最後まで | Tab の応答(中央値 / 最大) |
| --- | ---: | ---: | --- |
| 前(毎回計算) | 58.6% | 15/29 | 約 500 ms / 1000 ms |
| すぐ(0 秒) | 62.1% | 16/29 | 536 ms / 990 ms(裏が間に合わず、その場で計算) |
| 0.3 秒 | 58.6% | 12/29 | 44 ms / 649 ms(軽い予測を使う) |
| 1 秒 | 58.6% | 15/29 | **43 ms / 58 ms**(作り直した予測を使う) |

負荷試験(RTX 3060、Standard):

| | 前 | 後 |
| --- | --- | --- |
| 変換 p95 / 最大 | 5564 ms / 8227 ms | **282 ms / 613 ms** |
| 入力中の候補 p95 | 6 ms | 6 ms |

変換の正確さは変わらない(前の文あり): AJIMEE Low 86.5%、Standard 91.5%、High 92.5%。慣用句・
ニュアンスも同じ。
