# 0004: システム辞書のバイナリ形式

- 状態: 採用
- 日付: 2026-09-28

## 背景

5.3 は、読みをキーとするダブル配列トライ(共通接頭辞検索と予測検索)、Mozc 品詞体系の
連接コスト行列(i16)、ヘッダにマジック `KTRD`・形式バージョン・SHA-256・セクション
オフセットを持つリトルエンディアンの形式を求める。細部は決まっていない。

## 決定

形式バージョン 3。

- ヘッダ 64 バイト + セクション表(7 × (オフセット u64, 長さ u64))。SHA-256 はヘッダと
  セクション表より後ろの全バイトに対して計算する。各セクションは 8 バイト境界に揃える。
- セクションは順に、トライ、読みの表、読み、エントリ、表記、連接行列、品詞分類。
- 読みは符号化して置く。カタカナ(U+30A1〜U+30FC)は1文字1バイト(1〜0x5C)、それ以外は
  0xFF に続けて UTF-8。1文字ずつ区切れる符号なので、符号の前方一致は読みの前方一致と一致する。
  Mozc の読みでカタカナ以外を含むのは約 1,700 件だけで、UTF-8 の約 3 分の 1 になる。
- トライは `yada`(ダブル配列、MSRV 1.58、依存なし)。キーは符号化した読み、値は読みの表の添字。
- 読みの表は 8 バイト(読みのオフセット u32、先頭エントリ u32)で、符号の順に並ぶ。末尾に番兵を
  置き、読みの長さとエントリの件数は次の件との差で求める。予測検索はこの表を二分探索する。
- エントリは 12 バイト固定長(表記のオフセット u32、表記の長さ u8、フラグ u8、lid、rid、コスト)。
  同じ読みのエントリは連続し、コストの昇順に並ぶ。フラグの下位 4 ビットは属性、上位 2 ビットは
  「表記が読みのカタカナそのまま」「読みのひらがな」を表し、そのときは表記を持たない。
- 表記は UTF-8 を連結し、同じ文字列は1回だけ置く。255 バイトを超える表記は受け付けない。
- 品詞分類は文脈 ID ごとの u8(0: 自立語、1: 付属語、2: 接頭辞)。文節区切りに使う(docs/adr/0005)。
- 構築時にエントリを (読みの符号, コスト, lid, rid, 表記, フラグ) で整列し、完全な重複を除く。
  入力の順序によらず同じバイト列になる(REQ-5-5)。
- 読み込み時に、マジック・バージョン・SHA-256・各セクションの範囲・全参照の範囲と
  UTF-8・読みの表の整列・トライと読みの表の対応を検証する。以後の検索は壊れたデータでパニックしない。

## 大きさ(Mozc dictionary_oss、1,284,925 エントリ)

| セクション | v2 | v3 |
| --- | ---: | ---: |
| トライ | 20.6MB | 10.3MB |
| 読みの表 | 11.9MB | 6.0MB |
| 読み | (文字列に含む) | 4.7MB |
| エントリ | 20.6MB | 15.4MB |
| 表記(v2 は読みを含む文字列) | 23.7MB | 8.5MB |
| 連接行列 | 14.3MB | 14.3MB |
| 合計 | 91.1MB | 59.2MB |

5.3 の目標(60MB 以下)に対して余裕が少ない。補助語彙を加えるときは、連接行列の圧縮
(行の重複はほぼないので、値の差分符号化など)を検討する。
