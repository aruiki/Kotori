# 0038. 診断情報と異常終了の記録に、入力した文字を入れない

- 状態: 採用
- 日付: 2026-10-01
- 関係: SPEC 13.3、REQ-15-2、docs/adr/0037(G6)、作業カード 42

## 背景

SPEC 13.3 は「クラッシュ時はミニダンプをローカルに保存し、設定画面に『診断情報を書き出す』を設ける(入力内容は含めない)」
としている。利用者から不具合の報告を受けるには、版・環境・AI の状態と、落ちた場所が要る。

ミニダンプは、いちばん小さい `MiniDumpNormal` でも全スレッドのスタックのメモリを含む。IME の変換サーバーのスタックには、
読み・候補・前の文の断片が残っている(短い文字列はスタックの上に置かれる)。「入力内容は含めない」とミニダンプは両立しない。

## 選択肢

| 案 | 落ちた場所 | 入力した文字 | 評価 |
| --- | --- | --- | --- |
| A. `MiniDumpNormal` | 変数まで分かる | スタックに残ったものが入る | REQ-15-2 に反する |
| B. ミニダンプ + 書き出す前に利用者が確かめる | 同上 | バイナリなので利用者には確かめられない | 同上 |
| **C. 例外の種類と場所だけのテキスト** | 例外のコード、落ちたモジュールとオフセット、呼び出しの道筋(モジュール + オフセット) | 入らない(メモリを読まない) | **採用** |

## 決めたこと

1. `mozc_server` は、落ちたとき(未処理の例外、`abort`)に `LocalLow\Kotori\crash\crash-<日時>-<PID>.txt` を書く。中身は
   `time`・`version`・`kind`・`code`・`module`・`offset`・`frame` の行だけ。最新 5 個を残す。
2. 設定の「AI 変換」タブに「診断情報を書き出す...」を置く。中身(版、Windows、GPU、Kotori の設定、AI の状態、異常終了の記録)を
   画面に出してから、テキストファイルに保存する。送信はしない。
3. 診断情報は**許可した項目だけ**で組み立てる。AI の状態のファイルと異常終了の記録は、許可したキーの行だけを通す
   (将来ほかのコードが別の行を書き足しても、診断情報には出ない)。モデルのファイルのパスはユーザー名を含むので、
   指定の有無だけを出す。
4. 単体テスト(`//base:kotori_diagnostics_test`)で、入力した文字に当たる行が出ないこと、`abort` で記録が書かれることを確かめる。

## 結果

- 落ちた場所はモジュール + オフセットで分かる。関数名にするには、リリースと同じビルドの PDB が要る(今は残していない。
  必要になったら、リリースのワークフローで PDB を成果物として残す)。
- SPEC 13.3 の「ミニダンプ」は、この ADR の「例外の種類と場所だけの記録」に読み替える(SPEC の改訂案、カード 46 の PR に書く)。
