# 0014: 製品の目標 ― Mozc の安心と AI の精度を両立した「高品質版 Google 日本語入力」

- 状態: 採用(メンテナの決定。SPEC への反映は別の PR でメンテナの承認を得る)
- 日付: 2026-09-29
- 関係: docs/adr/0012(Mozc ベース)、0013(LM リランクの組み込み方)

## 背景

- 自前のフロントエンド(Rust の TIP)は、実機で安定させるための往復が多すぎた(ADR 0012)。
- Mozc に AI(zenz-v2.5)の並べ替えを組み込み、AJIMEE-Bench Acc@1 は Mozc 単体の 51.0% から 62.0% に
  上がった(ADR 0013)。
- azooKey-Windows(Zenzai を Windows で動かす IME、MIT)を試した。変換は独特で、飛び抜けて強くはない。
  学習・辞書登録・予測変換はまだない。
- 難しい例で弱点が見えた。「はがいたいので」が「葉が痛いので」になる(日本語として不自然)。
  文節だけを見て並べ替えていたためで、後ろの文節も含めて採点すると「歯が」に直った。

## 決定: 目標

**Mozc という安心のベースに AI を載せ、膨大なテストデータで難しい課題を解ける品質にする。
立ち位置は「高品質版 Google 日本語入力」。**

1. **土台は Mozc のまま**。学習・ユーザー辞書・予測・候補ウィンドウ・設定画面・TSF は Mozc のものを
   使い、自前で作り直さない。改変は `mozc/patches/` に小さく保つ。
2. **強みは AI の変換精度**。日本語として不自然な変換(「葉が痛い」など)は出さない。文脈で読みが
   分かれる課題(「今日歯医者」と「今日は医者」、「東京特許許可局今日急遽休暇」)を解く。
3. **品質は数字で示す**。「AI を積んだから良い」とは言わない。下の評価で Google 日本語入力と比べ、
   勝っている数字だけを売りにする。
4. **ネットワークに触れない**(REQ-15-1)。AI は手元の CPU で動かし、モデルは配布物に入れる。

## 設計(ここまでと、これから)

| 層 | 内容 | 状態 |
| --- | --- | --- |
| 土台 | Mozc(google/mozc をコミットで固定)+ 名前と識別子の変更(パッチ 0001) | 済み(v0.2.0-beta.1) |
| AI の採点 | llama.cpp + zenz-v2.5(`rewriter/zenz_scorer`、パッチ 0002) | 済み(#79) |
| 並べ替え 1 | 文節ごとに上位 K 件を、左の文脈と後ろの文節も含めて採点する(`LmRewriter`) | 実装中 |
| 並べ替え 2 | 文全体の上位 K 文を採点し、文節の切り方も直す(ADR 0013 の選択肢 2) | 次 |
| 生成 | 候補にない正解を AI が作る(Zenzai の制約付き生成) | 並べ替えで足りなければ検討 |
| 品質の選択 | 設定画面で low / standard / high / unreal を選ぶ。モデルのファイルも選べる | 実装中(下の案) |
| 配布 | AI 入りの MSI を常に出す。CC BY-SA 4.0 の表示を同梱 | 実装中 |

品質の段階(案。数値を測ってから決める):

| 段階 | モデル | 目安 |
| --- | --- | --- |
| low | zenz-v2.5-xsmall(26M) | 古い PC 向け。速い |
| standard | zenz-v2.5-small q8_0(91M、同梱) | 既定 |
| high | small、候補を多く(K=16)、文全体の並べ替え | 精度寄り |
| unreal | zenz-v2.5-medium(310M) | 最高精度。速い CPU か GPU 向け |

## 評価: 「膨大なテストデータ」

| セット | 中身 | 目的 |
| --- | --- | --- |
| AJIMEE-Bench(200 問) | 公開の評価セット | 他の IME と同じ物差しで比べる |
| Kotori 難問セット | 文脈で読みが分かれる例、同音異義語、早口言葉、固有名詞、数字、記号。実際に使って見つけた誤変換を足していく | 「難しい課題を解ける」ことを示す |
| 大規模回帰セット | ライセンスの明らかなコーパス(Wikipedia など)から数万文。分野ごとに分ける | 1 つを直して他を壊していないか確かめる |
| Google 日本語入力との比較 | 上の各セットを Google 日本語入力でも変換して比べる | 立ち位置の根拠 |

守ること:
- 重みやモデルの調整は開発用の分割で行い、評価用の分割では調整しない(SPEC 7.3)。
- 精度が下がる変更は、PR に前後の比較を貼る(REQ-14-2)。
- 変換の遅延も測り、打鍵を妨げない(ADR 0008 の 2 段階応答)。

## 目標の数値(暫定。評価を作ったら見直す)

- AJIMEE-Bench Acc@1: 80% 以上(Rust 版の文全体の並べ替えで 79.5% が出ている)。
- Kotori 難問セット: Google 日本語入力を上回る。
- 大規模回帰セット: Google 日本語入力と同等以上、かつ Mozc 単体を下回る分野がない。
- 「日本語として不自然な第 1 候補」を 0 に近づける。

## 影響

- SPEC(docs/SPEC.md)は Rust のエンジンを前提にしている。この目標に合わせた改訂は、メンテナの承認を
  得る PR で行う。
- 旧 Rust 版(crates/、frontends/windows/)は、並べ替え 2 の参考実装として残す。
- azooKey-Windows と AzooKeyKanaKanjiConverter(MIT)は、Zenzai の生成と GPU のバックエンドの参考にする。
