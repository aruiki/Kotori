# 0029: 要求どうしの待ちの積み重なりをなくす(GPU のない PC)

- 状態: 採用
- 日付: 2026-09-30
- 関係: docs/adr/0024、0025

## 問題

負荷試験(`mozc/tools/stress_test.py`: いろいろな読みで入力中の候補・変換・Tab を間を置かずに送る)を、GPU を
使わず(`KOTORI_LM_DEVICE=cpu`、新しい Low)に回すと、変換 p95 931 ms・最大 1469 ms、Tab p95 305 ms だった
(Mozc 単体は変換の最大 173 ms)。原因は待ちの積み重なり:

- 変換がロックを離した直後に、裏の先回りの変換がロックを取り、続く第 1 候補の当てはめ・Tab が最大 0.3 秒ずつ待った。
- 先回りの変換の前置きの計算(CPU で約 0.25 秒)は途中でやめられなかった。
- 時間の上限を、ロックを取った後から数えていた。CPU では文節ごとの並べ替えにも別に上限がかかった。
- 長い読みの採点(候補 4 つ × 100 文字前後)は、1 回の計算で上限を超え、途中でやめられなかった。

## 決定

- 裏の先回りの変換は、要求(変換・Tab)の最中と、終わってから 150 ms はロックを取らない。変換した読みは
  やり直さない。先回りの変換を頼まない打鍵でも、前の読みの先回りの変換をやめさせる。
- 前置きの計算は、やめる関数があるときは 32 トークンずつにし、その間にやめられるようにする
  (GPU では呼ぶ回数が効くので、やめる関数がなければ 1 回で計算する)。
- GPU がないとき: 時間の上限は要求が来た時点から数える(この要求の中でモデルを読み込んだときは、読み込みの
  後から)。60 文字を超える読みでは AI を使わない。文節ごとの並べ替えはしない(文全体の選択だけ)。
- AI を使わない場面(LLM がないときの Tab、GPU がなく長い読み)では、ロックを取る前に抜ける。

## 結果

負荷試験(381 コマンド):

| | 変換 p50 / p95 / 最大 | Tab p95 / 最大 |
| --- | --- | --- |
| CPU、前 | 246 / 952 / 1492 ms | 316 / 322 ms |
| CPU、後 | **129 / 631 / 795 ms** | **6 / 7 ms** |
| GPU、後 | 65 / 269 / 439 ms | 732 / 860 ms(キャッシュのない Tab、docs/adr/0025) |

精度は変わらない(AJIMEE Low 88.0%、Standard 91.5%、High 92.5%、日常 97.5%)。Standard の AI の稼働率
(`cost_bench.py`)は 49.9% → 46.6%。
