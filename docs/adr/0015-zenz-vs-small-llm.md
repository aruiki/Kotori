# 0015: 採点役は zenz のまま。LLM の併用は保留し、候補の出し方を先に直す

- 状態: 採用
- 日付: 2026-09-30
- 関係: docs/adr/0013、0014

## 背景

「LLM を使えば文脈を理解できるのでは」という問いに答えるため、Mozc 単体の候補(文節ごと上位 8 件)を、
採点役だけ入れ替えて比べた。手順は `eval/tools/dump_cands.py`(候補の書き出し)と
`eval/tools/llm_rerank.py`(文全体の log P で文節ごとに選び直す。Mozc の順位も 0.5/位 加味)。
RTX 3060、bf16。速さはこの素朴な実装での相対値。

| 採点役 | 大きさ | AJIMEE 200 | 慣用句 25 | ニュアンス 20 | 速さ |
| --- | --- | ---: | ---: | ---: | ---: |
| なし(Mozc 単体) | - | 51.0% | 88% | 55% | - |
| zenz-v2.5-xsmall | 26M | 65.0% | 88% | 65% | 135 ms |
| zenz-v2.5-small | 91M | 73.0% | 92% | 65% | 267 ms |

問題セット: 慣用句 `eval/sets/kotori-idioms.json`、ニュアンス `eval/sets/kotori-nuance.json`(Kotori 難問セットの始まり)。

## わかったこと

1. zenz-small(91M)は 10〜20 倍大きい LLM と同等。変換専用の学習の効果が大きい。
2. 最良の LLM(TinySwallow-1.5B)でも zenz-small より +3.5 pt。GPU を求めるほどの差ではない。
3. 「あの世に逝った」はどのモデルも直せない。
4. 全モデルが落とす問題の多くは、正解が候補にない(「今日|歯医者」「胃に」「貴社の記者が汽車で帰社」)。
   Mozc の文節の切り方が固定されているため。

## 決定

1. 採点役は zenz-small(CPU)を既定のまま。Unreal は zenz-medium。
2. 次は候補の出し方を直す: 文全体の N-best と、区切りの違う候補を出す(ADR 0013 の選択肢 2)。
3. LLM の併用は保留。2 のあとに測り直し、はっきり伸びるなら入れる。そのときは GPU を
   Vulkan(llama.cpp)で使い、CUDA Toolkit などをユーザーに入れさせない。GPU がなければ
   黙って zenz だけで動く。
