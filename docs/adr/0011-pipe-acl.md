# 0011: パイプの ACL を AppContainer と低整合性に広げ、接続元をトークンで確かめる

- 状態: 採用
- 日付: 2026-09-29

## 背景

REQ-10-4 では、ストアアプリ(AppContainer)と低整合性のプロセスからもエンジンにつながるよう、
名前付きパイプに「すべてのアプリケーションパッケージ」と低整合性ラベルを付ける。そのうえで、
接続元が同じユーザーであることを必ず確かめる。今のパイプは、保護付き DACL で同じユーザーにだけ
全権を与えている。そのため AppContainer と低整合性のプロセスはつながらない。

## 決定

- セキュリティ記述子を `D:P(A;;GA;;;<ユーザーSID>)(A;;0x12008b;;;AC)S:(ML;;NW;;;LW)` にする
  (`kotori_client::acl::pipe_sddl`)。
  - `AC`(すべてのアプリケーションパッケージ)に与えるのは `FILE_GENERIC_READ | FILE_WRITE_DATA`
    だけにする。`GENERIC_WRITE` には `FILE_APPEND_DATA` が含まれ、パイプではこれがインスタンスを
    作る権限(`FILE_CREATE_PIPE_INSTANCE`)になる。これを与えると、ほかのプロセスがパイプの
    インスタンスを作り、サーバーになりすませてしまう。
  - クライアントも `GENERIC_WRITE` を求めず、同じアクセス権(`PIPE_CLIENT_ACCESS`)で開く。
  - 整合性ラベルは低(`LW`、`NW` = 書き込みは上へ行かない)にし、低整合性のプロセスが書けるようにする。
- `AC` の許可はユーザーを問わない。そのためサーバーは接続を受けたら、
  `GetNamedPipeClientProcessId` → `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` →
  `OpenProcessToken(TOKEN_QUERY)` で接続元のユーザー SID を取り、自分と同じときだけ受け付ける。
  違うとき、または確かめられないときは切って次を待つ。
- 単一インスタンスのミューテックスは、今までどおり本人だけに許す(サーバーしか開かない)。

## 検討した別案

- 接続元の確認に、プロセス ID ではなく `ImpersonateNamedPipeClient` と `OpenThreadToken` を
  使う案。クライアントは偽装レベルを「識別」にして開くので、どちらでもトークンは読める。
  プロセス ID は接続が生きている間は使い回されないので、実装の短い前者にした。

## 影響

- 管理者として動くアプリ(昇格したプロセス)からの接続も、同じユーザーのトークンなら受け付ける。
  ただし昇格したプロセスのトークンを中整合性のサーバーから読めない環境があれば、そのアプリでは
  キーが渡される(直接入力になる)。実機で確かめる。
- renderer のパイプ(docs/adr/0010、作業カード 13)でも同じ記述子と確認を使う。
