# 0016: zenz で生成し、zenz と LLM(GPU)で選ぶ

- 状態: 採用(メンテナの指示「GPU ありの LLM 中堅モデルを基本に、精度 90% 以上」に基づく)
- 日付: 2026-09-30
- 関係: docs/adr/0013、0014、0015

## 背景

ADR 0015 までの「Mozc の候補を選び直す」方式は、AJIMEE-Bench(前の文あり)76.0% で止まった。
間違いの多くは、正解が候補にないこと(文節の切り方、辞書にない語)による。azooKey(Zenzai)は
AI が変換を**生成**するので 85% 出る(推論 5 回、zenz-v3.2-small、前の文あり)。

Python の下見(`eval/tools/`、2 分割の交差検証)で、zenz-v2.5-small がビーム 4 で生成した文と
Kotori の結果を合わせ、zenz と LLM(TinySwallow-1.5B)の点数の和で選ぶと 90.5% になった。

## 決定

変換の最初(区切りが決まっていないとき)に、次の手順で文を選ぶ(`rewriter/lm_rewriter.cc`)。

1. 候補を集める: ラティスの文全体の候補(区切り付き、上位 4 件)+ zenz が読みと前の文から
   ビームサーチで生成した文(8 件。品質 Low は 2 件)。
2. 生成した文は、読みに過不足なく合うかを辞書で確かめる(辞書の語、単漢字辞書の読み、連濁、
   同じかな・記号、数字と英字)。読みを落とした文(「た。」で終わるなど)を除く。
3. 点数 = zenz の log P(文 | 読み、前の文) + LLM の log P(文 | 前の文)。LLM がなければ zenz だけ。
4. 最良の文の区切りで文節を切り直す。生成した文は全体を 1 文節にする。

モデルと実行環境:

| 役割 | モデル | 大きさ | 動く場所 |
| --- | --- | --- | --- |
| 生成と採点 | zenz-v2.5-small(q8_0) | 95 MB | CPU / GPU |
| 採点(文脈と意味) | TinySwallow-1.5B(Q5_K_M、Apache-2.0) | 1.1 GB | GPU(Vulkan)。「自動」なら GPU があるときだけ |

- llama.cpp は公式の Windows ビルド(b11259、Vulkan 版)の DLL を同梱し、実行時に読み込む
  (`rewriter/llama_runtime.cc`)。ggml が GPU と CPU の種類ごとの DLL から使えるものを選ぶので、
  ユーザーは CUDA Toolkit などを入れなくてよい。GPU がなければ zenz だけで動く。
- 設定画面の「AI モデル」: 自動(既定)/ zenz のみ / zenz + LLM。LLM のファイルは差し替えられる。
- 「中堅の LLM」には TinySwallow-1.5B を選んだ。小さな LLM の比較(ADR 0015)で最も良く、
  MSI の上限(2 GB)に収まる。3B 級は MSI に入らない。

## 結果(AJIMEE-Bench 200 問、RTX 3060、Windows の `converter_main`)

| 構成 | AJIMEE | AJIMEE(前の文あり) | ニュアンス 20 | 慣用句 25 | 速さ |
| --- | ---: | ---: | ---: | ---: | ---: |
| Mozc 単体 | 51.0% | - | 55% | 88% | - |
| ADR 0015(選び直しのみ) | 73.0% | 76.0% | 70% | 92% | - |
| **zenz 生成 + zenz・LLM で選ぶ(GPU)** | **87.5%** | **91.5%** | 80% | 96% | 1 問 約 0.25 秒 |
| zenz 生成 + zenz で選ぶ(GPU なし) | - | 85.0% | 80% | 92% | CPU で 1 問 約 2 秒 |
| (参考)azooKey + Zenzai(推論 5 回) | 79.0% | 85.0% | 75% | 84% | 約 0.1 秒 |

注意: 生成する文の数(8)とラティスの候補数(4)は、AJIMEE で数通りを比べて選んだ(差は 1〜2 問)。
評価セットで選んだ値なので、開発用のセット(ADR 0014 の大規模回帰セット)を作ったら選び直す。

## 分かったこと

- 生成の効果が大きい(選び直しだけの 76.0% → 生成を加えて zenz だけでも 85.0%)。
- LLM は、生成した候補の中から文脈に合うものを選ぶ役で効く(+6.5 pt)。
- `convert_hf_to_gguf.py --outtype q8_0` で直接作った TinySwallow の GGUF は壊れる(対数確率が
  -8 → -96 になる)。f16 にしてから `llama-quantize` で量子化する(`training/llm/make.sh`)。
- zenz の判定は語彙の大きさで行う(zenz は 6000、LLM は数万以上)。

## 影響

- MSI は約 1.25 GB になる(LLM 1.1 GB を含む)。
- 残る間違いは、数字の書き方(三年/３年)、表記の好み(殆ど/ほとんど)、辞書にない固有名詞。
  辞書の拡張(Mozc UT)と開発用セットでの調整で詰める。
