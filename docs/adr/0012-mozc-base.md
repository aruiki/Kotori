# 0012: Mozc をベースにし、Kotori の LM リランクを組み込む

- 状態: 採用(メンテナが判断を任せた。SPEC の改訂は別の PR でメンテナの承認を得る)
- 日付: 2026-09-29

## 背景

v0.1.0-beta.1〜3 を実機で使ったメンテナから、次の報告があった。

- 半角/全角キーでの IME のオン/オフ、待機中の Space、Ctrl+Backspace、入力モードの表示を
  beta.3 で直したが、実機ではうまく直らなかった。
- 候補ウィンドウは描画がまだない(Issue #54 の判断待ち)。

IME のフロントエンド(TSF の細かい動き、候補ウィンドウ、入力モード、設定画面、ユーザー辞書、
学習、予測、確定アンドゥ、アプリごとの癖への対処)は、Linux の CI では確かめられず、実機での
往復が要る。Kotori の強みはそこではなく、LM のリランクによる精度(AJIMEE-Bench Acc@1 が
ラティス単体の 53.0% から 79.5%)にある。

## 選択肢

1. **Mozc をベースにする(採用)**。Mozc の変換エンジン・TSF フロントエンド・候補ウィンドウ・
   設定画面(Qt)をそのまま使い、Kotori の LM リランク(zenz-v2.5 と llama.cpp)を Mozc の
   変換に組み込む。
   - 利点: フロントエンドは長年使われていて、今つまずいている部分がすべて揃っている。
     BSD-3-Clause なので改変して配布できる。辞書はすでに Mozc の dictionary_oss を使っている。
     Windows のインストーラ(MSI)を GitHub Actions で作る手順が公式にある(`windows.yaml`)。
   - 欠点: Rust のエンジン・サーバー・IPC・TIP の大半は使わなくなる。Mozc は大きな C++ で、
     Bazel のビルドは重い(公式の CI で 1 ジョブ最大 120 分)。SPEC の大きな改訂が要る。
2. Kotori を続け、Mozc の TSF フロントエンドのコードを参考に作り直す。自前のエンジンは残るが、
   実機で安定するまでの往復が多く、利用者が使える状態になるまで時間がかかる。
3. Kotori のエンジンを残し、Mozc のフロントエンドを Kotori のサーバーにつなぐ。両者の
   プロトコルと状態の持ち方を合わせる手間が大きい。

## 決定

選択肢 1。次の段階で進める。

1. **素の Mozc を CI でビルドする**。`google/mozc` をコミットで固定して取得し、
   `.github/workflows/mozc-windows.yml` で `Mozc64.msi` を作る。改変はまだしない。
   ビルドが通ること、実機でオン/オフ・候補ウィンドウが動くことを確かめる。
2. **名前と識別子を Kotori に変える**。公式の Mozc や Google 日本語入力と並べて入れられるよう、
   製品名・CLSID・プロファイルの GUID・パイプ名などを変える。BSD-3-Clause の第3項により、
   Google の名前を推奨の表示に使わない。改変は `mozc/patches/` のパッチとして持つ。
3. **LM リランクを組み込む**。Mozc の変換結果の上位候補を zenz-v2.5-small(8 bit 版、
   AJIMEE-Bench Acc@1 79.0%、f16 は 79.5%)で並べ替える。llama.cpp は `third_party/llama.cpp`
   と同じコミットを使う。2段階応答(docs/adr/0008)の考え方を Mozc の中で実装する。
4. **評価と配布**。`kotori-eval` の評価(AJIMEE-Bench)を Mozc ベースでも回せるようにし、
   前後の数値を比べる。モデルを同梱した MSI をリリースにする(同梱の判断はメンテナが案 B
   「常に AI 入り」を選んだ)。

## 影響

- `crates/` の Rust のエンジンと `frontends/windows/` の TIP は、段階 3 が終わるまで残す
  (評価の基準と LM リランクの参考実装)。新しい機能は足さない。
- 作業カード(`docs/tasks/`)は段階ごとに書き直す。
- ライセンス: Mozc は BSD-3-Clause、Qt は LGPL-3.0(Mozc の配布物は DLL で動的リンク)、
  zenz-v2.5 は CC BY-SA 4.0。配布物に全文と帰属表示を入れる。
- REQ-15-1(ネットワークに触れない)は Mozc の OSS 版でも守られているが、段階 2 で確かめる。
